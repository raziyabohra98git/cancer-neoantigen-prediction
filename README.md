# Cancer Neoantigen Candidate Prioritization

A reproducible Python demonstration of a computational workflow for prioritizing candidate cancer neoantigens using mutant-versus-wild-type peptide binding comparisons and AI-assisted ranking.

The workflow is informed by a five-patient TCGA-LUAD in-silico pilot completed during a Bioinformatics, AI & Machine Learning internship.

## Important: Synthetic Demonstration

All data generated by the public demo are synthetic.

- Candidate and sample identifiers are placeholders.
- Gene symbols are synthetic labels, not observed cancer genes.
- Peptide sequences are randomly generated for software testing.
- Binding affinity and percentile values are simulated, not MHCflurry predictions.
- AI scores and feature-importance values are demonstration outputs, not results from the internship analysis.
- Pathway enrichment is skipped for synthetic placeholder genes.

The original patient-level internship data, HLA assignments, mutation records, and project-derived prediction tables are not included.

## Workflow

1. Generate synthetic candidate, mutant-prediction, and wild-type-prediction tables.
2. Perform quality control on mutant binding predictions.
3. Apply the primary MHC class I binding filter.
4. Match wild-type predictions using the WT peptide sequence and HLA allele.
5. Compare mutant and wild-type binding predictions.
6. Assign mutually exclusive biological priority categories.
7. Calculate AI-assisted ranking scores using three machine-learning models.
8. Generate synthetic candidate, gene, sample, HLA, and cancer-gene reference summaries.
9. Provide a pathway-analysis interface with a guard against interpreting synthetic genes biologically.

## Binding and Prioritization Rules

### Primary binding filter

Candidates pass the primary filter when both conditions are met:

- Mutant affinity <= 500 nM
- Mutant binding percentile <= 2

### Stringent binding filter

The stringent filter requires:

- Mutant affinity <= 50 nM
- Mutant binding percentile <= 0.5

### Priority 1

Priority 1 requires all stringent criteria, plus both conditions:

- WT affinity divided by mutant affinity >= 2
- WT percentile divided by mutant percentile >= 2

Lower affinity and lower percentile indicate stronger predicted binding.

Priority 2 identifies stringent candidates with stronger mutant binding on both measures that do not satisfy every Priority 1 requirement.

Priority 3 identifies the remaining candidates that pass stringent binding.

Candidates that do not pass the stringent thresholds are classified as below stringent.

These categories are computational prioritization rules, not evidence of experimental immunogenicity.

## AI-Assisted Ranking

The demonstration uses eight features:

- `mhcflurry_affinity`
- `mhcflurry_affinity_percentile`
- `WT_Binding_Affinity`
- `WT_Binding_Percentile`
- `affinity_fold_improvement`
- `percentile_fold_improvement`
- `Peptide_Length`
- `Mutation_Position_in_Peptide`

The models are Random Forest, XGBoost, and Logistic Regression.

The combined score is:

`AI_score = 0.40 × RF_score + 0.30 × XGB_score + 0.30 × LR_score`

The final ranking combines this score with priority weights: Priority 1 = 3, Priority 2 = 2, Priority 3 = 1, and below stringent = 0.

### ML interpretation limitation

The Priority 1 label is derived from binding and mutant-versus-WT rules that overlap with the model features. The models are fitted and scored on the same demonstration dataset.

Consequently, the scores demonstrate an AI-assisted ranking workflow. They do not establish independent predictive performance, generalization to unseen patients, or experimental immunogenicity.

Feature importance from synthetic data must not be interpreted as biological evidence.

## Installation

Use Python 3.11 in a dedicated environment.

Create the environment with micromamba:

`micromamba create -n neoantigen-demo -c conda-forge python=3.11 pip`

Activate it:

`micromamba activate neoantigen-demo`

Install the dependencies:

`python -m pip install -r requirements.txt`

## Run the Demonstration

Execute the complete workflow:

`./run_demo.sh`

Run the automated tests:

`python -m pytest -q`

The pipeline regenerates synthetic input tables and writes its output tables and quality-control logs to `example_results/`.

Generated results are ignored by Git and can be recreated at any time by running the demo.

## Repository Structure

- `src/` — analysis and quality-control scripts
- `example_data/` — explicitly synthetic input tables
- `example_results/` — generated output tables and QC logs
- `tests/` — automated tests
- `docs/` — methodology, data dictionary, and limitations
- `workflow/` — workflow diagram
- `run_demo.sh` — one-command demonstration workflow

## Scientific and Practical Limitations

Binding predictions alone do not establish peptide processing, cell-surface presentation, T-cell recognition, immunogenicity, safety, or vaccine efficacy.

A real-data analysis requires validated somatic mutations, correctly linked patient-specific HLA information, genuine mutant and WT prediction results, an appropriate biological background, and experimental follow-up.

The repository is an educational portfolio demonstration, not a clinical decision-support tool.
