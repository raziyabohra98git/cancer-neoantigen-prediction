# Methodology and Decision Rules

## 1. Scope

This repository demonstrates a reproducible workflow for candidate cancer
neoantigen prioritization. All data generated by the public demonstration
are synthetic. They do not represent real patients or validated neoantigens.

## 2. Workflow

The pipeline performs these stages:

1. Generate synthetic candidate and binding-prediction data.
2. Validate mutant binding-prediction data.
3. Apply primary MHC class I binding filters.
4. Match wild-type (WT) predictions to candidate peptides.
5. Compare mutant and WT binding measurements.
6. Assign priority categories using explicit rules.
7. Generate AI-assisted candidate rankings.
8. Produce gene, mutation, patient, and HLA summaries.
9. Provide a pathway-analysis interface.

## 3. Binding filters

The primary binding filter requires both:
- Mutant affinity <= 500 nM.
- Mutant binding percentile <= 2.

The stringent mutant-binding filter requires both:
- Mutant affinity <= 50 nM.
- Mutant binding percentile <= 0.5.

Lower affinity and percentile values indicate stronger predicted binding.
Predicted binding alone does not establish immunogenicity.

## 4. Mutant-versus-WT comparison

Affinity fold improvement is calculated as WT affinity divided by mutant
affinity. Percentile fold improvement is calculated as WT percentile divided
by mutant percentile.

A ratio greater than 1 indicates a lower predicted value for the mutant
than for the corresponding WT peptide for that metric.

## 5. Priority assignment

Priority 1 requires all four criteria:

- Mutant affinity <= 50 nM.
- Mutant percentile <= 0.5.
- WT affinity divided by mutant affinity >= 2.
- WT percentile divided by mutant percentile >= 2.

The other priority categories are assigned by the rules implemented in
`src/priority_classification.py`. Priority categories are computational
labels, not experimental or clinical validation.

## 6. AI-assisted ranking

The demonstration uses three model types:

- Random Forest.
- XGBoost.
- Logistic Regression.

The ensemble score is calculated as:

AI score = 0.40 * RF score + 0.30 * XGBoost score + 0.30 * Logistic Regression score

The models use eight features covering mutant and WT binding, fold-improvement
ratios, peptide length, and mutation position. Exact column names and model
settings are defined in `src/ml_ranking.py`.

The final rank score combines the priority weight and AI score. The weights
are 3 for Priority 1, 2 for Priority 2, 1 for Priority 3, and 0 for candidates
below the stringent threshold.

### Important model limitation

The priority labels are derived from rules related to the model features.
The demonstration fits and scores models on the same synthetic dataset.
Therefore, the resulting AI scores do not establish independent
immunogenicity, prospective predictive performance, or clinical utility.

## 7. Gene and pathway analysis

The gene-analysis stage summarizes candidate genes and checks overlap with a
reference list. A lack of overlap is reported rather than used to force a
biological conclusion.

Pathway enrichment is intentionally skipped for the synthetic demo because
placeholder gene symbols cannot support meaningful biological interpretation.
The presence of a pathway-analysis interface is not evidence of enrichment.

## 8. Reproducibility

From the repository root, run `./run_demo.sh` to regenerate the synthetic
demonstration outputs. Run `python -m pytest -q` to execute the automated
tests.

Generated demo outputs are not clinical or research findings. Before using
this workflow with real data, verify data permissions, input formats, model
assumptions, and the suitability of the analysis for the research question.
